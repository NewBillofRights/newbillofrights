> # Deploy logging — full output to a temp file, monitored live

> Deploys fail in the middle, print the reason once, and scroll it away. A deploy
> run with `| tail -15` or bare truncated output is undebuggable after the fact.
> Every deploy MUST follow this recipe — no exceptions, even for "quick" ones.

> ## The recipe

> 1. **Pick a log path** (persistent temp dir, survives the session):

>    ```bash
>    LOG=/tmp/deploy-logs/<repo>-<script>-$(date +%Y%m%d-%H%M%S).log
>    mkdir -p /tmp/deploy-logs
>    ```

> 2. **Launch the deploy in the background with ALL output going to the log**
>    (use the Bash tool's `run_in_background: true`, not `&`):

>    ```bash
>    <deploy command> > "$LOG" 2>&1; echo "DEPLOY EXIT: $?"
>    ```

>    Never pipe the live deploy through `head`/`tail`/`grep` as the only sink —
>    filters are for reading the log, not for capturing it.

> 3. **Immediately arm a Monitor on the log** so progress streams into the chat
>    like a terminal:

>    ```
>    Monitor: tail -n +1 -f "$LOG" | grep --line-buffered -E "✔|✖|Error|error:|Failed|failed|Deploy complete|Hosting URL|Compiled|uploading|release|denied|EXIT"
>    ```

>    The filter must cover FAILURE signatures, not just success lines — silence
>    must never be mistaken for progress.

> 4. **On completion**: report the exit code, the key result lines (e.g. Hosting
>    URL / release id), and ALWAYS include the log path in the summary so the
>    user can inspect it later.

> 5. **On failure**: Read the FULL log file (not just the tail) before
>    diagnosing — firebase/gcloud print root causes mid-stream (auth errors,
>    quota, build failures) far above the final generic error line. Keep the log;
>    never delete it.

> ## Notes

> - Applies to: `firebase deploy` (any flags), `pnpm deploy:*`, `npm run deploy*`,
>   `gcloud app/run/functions deploy`, `vercel`, `netlify deploy`, store uploads,
>   and any rsync/scp that ships build artifacts to a server.
> - Verification after deploy is separate and still required (curl the deployed
>   URL / check a marker); the log is for the deploy itself.
> - [REDACTED] specifics: deploys use the globally-pinned firebase-tools (15.22.1);
>   never `npx firebase-tools@latest` for deploys (see the version-split memory).
